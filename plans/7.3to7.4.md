## Version decisions (changed from the original ask, with reasons)

- **Core 7.4.12 instead of 7.4.11.** 7.4.12.Final is now the newest 7.4 patch on Maven Central (2026-10-07); same
  minor line, so it is taken.
- **Tools = `org.hibernate.orm:hibernate-reveng:7.4.12.Final`, not `hibernate-tools-orm:7.3.13`.** From 7.4 Hibernate
  Tools moved into the ORM repository and is released in lockstep with core as `hibernate-reveng`
  ([announcement](https://in.relation.to/2026/05/04/hibernate-tools-moves-to-orm/)). That gives an aligned pair again,
  matching the "aligned core/Tools pairs" decision. Its API is javap-identical to tools-orm 7.3.13 after a package
  rename. Mixing tools-orm 7.3.13 with core 7.4.12 also mostly works at the binary level, but its `DdlExporter`
  needs `SchemaExport`/`SchemaUpdate`, which are no longer in `hibernate-ant:7.4.12` (`NoClassDefFoundError`) — so the
  mixed pair is recorded as an open risk, not used.

## Step 1 — build

- `org.hibernate.orm:hibernate-core:7.4.12.Final` (declared explicitly: `hibernate-reveng` only has core at runtime scope).

  again in 7.4; not needed by these demos) plus the 7.3 excludes if still present.

## Step 3 — core 7.3 → 7.4

Javap diffs of every core class the demos use are purely additive (nothing removed or newly deprecated), so no
core source change is expected. Behaviour to watch in the run:
- `PostgreSQLDialect()` no-arg now assumes version **14** (was 13) → `DialectsMain` output.
- `setMaxResults` + collection `join fetch` is applied in SQL rather than in memory (the demos do not combine them).
- MySQL dialect no longer defaults `max_fetch_depth=2` (not used here).

## Open risks

- Using tools-orm 7.3.13 with core 7.4.12 (e.g. if a project can't take `hibernate-reveng` yet): fine for

## Results (2026-10-07)

**Done.** `./gradlew clean build`: 0 compiler warnings. `./gradlew run`: all 8 Mains OK. Core needed no source
change; every Tools import mapped 1:1 to a `hibernate-reveng` class (the `EnhancedValue` path is
`org.hibernate.tool.reveng.internal.core.util.EnhancedValue`). `hibernate-ant` is no longer on the classpath.

Found during the run (not in the research):
- **`AbstractExporter.start()` now calls `stop()`**, which closes the service registry of the exporter's `Metadata`
  and clears it. The 7.3 code's `finally { ((MetadataImpl) exporter.getMetadata())...destroy(); }` therefore
  *re-built* the whole reverse-engineered `Metadata` just to destroy it. `ExporterMain` drops that cleanup on 7.4 and
  says so; `start(false)` keeps the old behaviour. `MetadataDescriptor.createMetadata()` still leaves its registry
  open, so the other Mains keep their explicit `destroy()`.

Output differences vs `hibernate-6-to-7`: Tools package names in class names/log lines, `PostgreSQLDialect()` version
14, and the notes above. SQL, statement counts and results are identical.

Open issues: none. (The mixed-pair risk — tools-orm 7.3.13 on core 7.4.12 — remains documented above but is not used.)
