# Hibernate Tools 5.6.15 → 6.6.58 / 7.3.13 API mapping

How this was checked: `javap -p -s -constants` on all three jars, plus a reading of the `-sources.jar` files for `hibernate-tools-orm` 6.6.58 and 7.3.13 and of the 5.6.15 sources. Jars and extracted sources are in `scratchpad/jars/` (`src5/`, `src6.6.58/`, `src7.3.13/`).

**Key fact:** the public and internal APIs of **6.6.58 and 7.3.13 match signature-for-signature** for every class listed below. A `javap` diff showed only private-member and lambda-name differences, plus `Cfg2JavaTool.getGenericCollectionDeclaration(Collection, ImportContext)` in 7.3, which in 6.6 also takes `boolean, `. So one port covers both versions; only the Maven coordinates/deps and Java baseline differ (6.6 = Java 11 bytecode (major 55), 7.3 = Java 17 (major 61)).

**Second key fact:** from ORM 7.4, Tools **moved into the hibernate-orm repo** as `org.hibernate.orm:hibernate-reveng` (versions 7.4.0.CR1 … 7.4.12.Final, 8.0.0.Beta*), with packages renamed: `org.hibernate.tool.api.reveng.*` → `org.hibernate.tool.reveng.api.core.*`, `org.hibernate.tool.api.{export,metadata}` → `org.hibernate.tool.reveng.api.{export,metadata}`, `org.hibernate.tool.internal.reveng.{strategy,dialect}` → `org.hibernate.tool.reveng.internal.core.{strategy,dialect}`, `org.hibernate.tool.internal.{util,export.*}` → `org.hibernate.tool.reveng.internal.{util,export.*}`. A `javap` diff of `hibernate-reveng-7.4.12.Final.jar` against tools-orm 7.3.13, after normalizing packages, is **identical** for all classes in this table. The only change: `AbstractExporter` gains `start(boolean)` and `stop()`. **The `ExporterConstants` / `MetadataConstants` string values are unchanged** (still `"org.hibernate.tool.api.export.ExporterConstants.…"`). No relocation POMs are published.

Abbreviations: `T` = `org.hibernate.tool`. 6.6.58 and 7.3.13 share one column because their signatures are identical.

## Item 20 — hibernate.reveng.xml

- **No DTD/XSD is bundled** in tools 5.6.15, tools-orm 6.6.58, tools-orm 7.3.13, or hibernate-reveng 7.4.12. `unzip -l` shows no `.dtd` or `.xsd` files, and the core jars contain none either. `OverrideRepository.addInputStream` builds a plain non-validating DOM parser with **no EntityResolver**. The JDK Xerces default `load-external-dtd=true` means **a `<!DOCTYPE … SYSTEM "http://hibernate.org/dtd/hibernate-reverse-engineering-3.0.dtd">` will still make the parser fetch the DTD over the network**: behaviour is unchanged, so keep stripping the DOCTYPE (or pre-parse yourself). This conclusion comes from reading the code, not a runtime test.
- **The format is unchanged.** `OverrideBinder.bindRoot` does not check the root element's name. It reads child elements `schema-selection`, `type-mapping` (only the first), `table-filter` and `table`. `type-mapping/sql-type` takes the attributes `jdbc-type`, `hibernate-type`, `length`, `precision`, `scale`, `not-null`. The set of string literals in `OverrideBinder` is identical between 5.6 and 7.3 (empty diff).
- **`"string"` and `"text"` still resolve.** `TypeUtils.determinePreferredType` looks the name up with `TypeConfiguration.getBasicTypeRegistry().getRegisteredType(name)`. `StandardBasicTypes` in core 6.6.58, 7.3.13 and 7.4.12 registers `"string"` (VARCHAR, 12) and `"text"` (LONGVARCHAR, -1), checked with javap. If the wanted type's SQL code differs from the DB column, Tools logs INFO and forces the column's sqlTypeCode. An unknown name only logs "No Hibernate type found …", and the name is still used as the type name.

## Item 21 — tools-orm 7.3.13 on hibernate-core 7.4.12

- **Source level:** all 7.3.13 Tools sources compile cleanly against core 7.3.13 **and** against core 7.4.12 (javac 21, `-proc:none`).
- **Binary level:** I extracted every `Methodref`/`InterfaceMethodref`/`Fieldref`/`Class` constant-pool entry for `org/hibernate/**` (excluding Tools' own classes) from all 199 classes and resolved each one through the class hierarchy in core 7.4.12 plus its dependencies. **All core classes and members resolve.** The one `JoinedList.<init>` miss was a script false positive caused by generics parsing; javap confirms both constructors.
- **Real break: `org.hibernate.tool.hbm2ddl.SchemaExport`, `SchemaExport$Action` and `SchemaUpdate`** are referenced by `T.internal.export.ddl.DdlExporter`. They live in `org.hibernate.orm:hibernate-ant:7.3.13`, but **`hibernate-ant:7.4.12` no longer contains them**: in 7.4 they moved to `org.hibernate.orm:hibernate-reveng:7.4.12`. If Gradle aligns hibernate-ant to 7.4.12 (for example through the `hibernate-platform` BOM or conflict resolution), using `DdlExporter` / `ExporterType.DDL` → `NoClassDefFoundError`. GenericExporter-only usage is unaffected. Keeping hibernate-ant at 7.3.13 next to core 7.4.12 is also possible, but that mixes versions.
- **Better option for core 7.4.x:** use `org.hibernate.orm:hibernate-reveng:7.4.12.Final`. Its API is identical to 7.3.13 except for the package renames listed at the top. It is released in lockstep with core.
