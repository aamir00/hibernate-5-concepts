# Plan: Hibernate 5.6 → 6.6 (branch `hibernate-6`)

| | |
|---|---|
| Branch | `hibernate-6`, based on `main` (this plans commit) |
| From | `org.hibernate:hibernate-core-jakarta` **5.6.15.Final** + `org.hibernate:hibernate-tools` **5.6.15.Final** |
| To | `org.hibernate.orm:hibernate-core` **6.6.58.Final** + `org.hibernate.tool:hibernate-tools-orm` **6.6.58.Final** |
| Why this pair | 6.6 is the last 6.x line; 6.6.58 is the newest 6.6 patch on Maven Central (2026-10-07), and the Tools 6.6.58 POM depends on core 6.6.58 (aligned pair). |
| Java / JPA | Java 11+ (project stays on toolchain 21) / Jakarta Persistence 3.1 (already `jakarta.*`, no package rename) |

| Research | [`research/orm6.md`](research/orm6.md) (migration guides 6.0–6.6 + javap + runtime probe), [`research/tools.md`](research/tools.md) (Tools 5.6 → 6.6/7.3 API map) |

## Ground rules (agreed)

- Every inventory row and every Main stays; renamed/removed APIs are replaced with the supported equivalent and the
  row prints a `CHANGED in 6:` / `REMOVED in 6:` note naming old → new API.
- Package `h5.concepts`, project name, class and file names are unchanged (clean `git diff`). No reformatting.
- One commit per logical step. No deprecation warnings left where a non-deprecated replacement exists.
- Done = `./gradlew clean build` + `./gradlew run` (RunAllMain) every Main OK + `run-output.txt` diffed against the
  5.6 baseline with every difference explained below or in "Results".

## Step 0 — baseline fix (first commit on the branch, before any upgrade)

`main`'s `BootstrapMain` row 6 calls `metadata.getSessionFactoryBuilder().build()` on reverse-engineered `Metadata`
whose entity classes (`com.demo.hr.*Entity`) were never generated/compiled. 5.6 throws
`MappingException: entity class not found`, so RunAllMain on `main` exits 1 (`BootstrapMain FAILED`).
`main` stays untouched, so the fix is the first commit of each upgrade branch: keep the call, catch the
`HibernateException`, print it as the **expected** result with a note. Then capture `run-output.txt` (5.6 baseline,
timings normalised to `<n> ms`) in the same commit so later commits show behaviour diffs.

## Decisions

- D1: Hibernate's own `@Cascade({PERSIST, MERGE, REMOVE})` on 6 (not JPA `cascade=`) — keeps row 20 about
  `org.hibernate.annotations.CascadeType` and is non-deprecated in 6.6. 7.x deprecates the whole enum (see `6to7.md`).
- D2: row 31 shows the internal `getJdbcCoordinator()` route (closest drop-in for `SessionImpl.connection()`), with the
  note that `doWork`/`doReturningWork` is the supported public API that wmstdappdbimpl should move to.
- D3: row 35 replacement = run the SQL through `doReturningWork` and read `ResultSetMetaData` (no Hibernate internal).
- D4: keep `hibernate.dialect` explicit (needed with metadata access off; matches the real module's config).
